# KOOK 运维中心

独立管理 Linux 服务器、网站与接口，以及现有 KOOK 机器人。网页位于 `/ops/`，需要现有 Sub2API **管理员**登录；额度看板仍保持原访问方式。

## 功能

- 服务器：CPU、内存、磁盘、负载、运行时长和最近 24 小时采集记录。
- systemd 服务：当前状态、进程、重启次数；管理员可重启配置白名单中的指定服务，保留请求和回执。
- 网站接口：每分钟 GET 检查状态码，可验证 JSON 字段；HTTPS 检查证书有效期。不会调用收费模型生成接口。
- 机器人：网关在线、语音频道、播放状态及采集到的错误；未采到或过期的信息明确显示未知。
- 连续 3 次异常发告警、2 次正常发恢复通知；维护模式暂停对应目标通知。不会自动重启任何服务。
- 思维2在两个授权文字频道响应 `状态`、`服务器状态`、`机器人状态`、`网站状态`、`运维帮助`。不需要斜杠指令，不调用模型。

服务器与机器人频道为 `4052889739856202`，网站接口频道为 `7255160236021294`。这两个目的地也在通知模块固定校验。讨论机器人程序是独立服务，保持停止；运维网关只使用思维2的 Token。

## 安装

服务端需要 Node.js 22.16+，采集端需要 Linux 和 Python 3.10+，均不需要第三方运行依赖。

```bash
cd ops-center
cp .env.example .env
cp config.example.json config.json
# 为每台主机生成独立随机 token，填写配置和私有 KOOK Token。
npm test
python3 -m unittest discover -s agent -p 'test_*.py' -v
npm start
```

服务端只监听本机端口 `18996`。反向代理示例见 `deploy/nginx-ops.conf`；它与现有 Sub2API、额度看板和 GitHub 桥接共用域名，不改变原路径。systemd 服务使用独立无登录用户 `kook-ops`，只能写自己的 `data/`。

每台被管理服务器安装 `agent/collector.py`，配置参见 `agent/config.example.json`，使用 `deploy/kook-ops-agent.service` 常驻采集。主机主动通过 HTTPS 上传，没有新增公网采集监听端口。采集配置与状态目录应只允许 root 读写。

```bash
python3 agent/collector.py --config /etc/kook-ops-agent/config.json --once
```

服务器 token 必须与服务端该 `hostId` 的 token 一致。采集器的服务白名单也必须与服务端一致；只有 `expected=running` 且 `restartAllowed=true` 的服务允许重启。讨论服务配置为 `expected=stopped`、`restartAllowed=false`。配置不能通过访客输入或 KOOK 消息修改。

没有 SSH 权限时，可使用独立的只读采集配置 `collectMetrics=false`、`services=[]` 从已有 HTTPS 音乐状态接口采集机器人。此模式的主机名称应明确标为“远程业务监控”，系统资源一律未知，也不能重启服务；它不能替代安装在目标主机上的完整采集器。

## 状态与可靠性

采集每 30 秒上传；主机记录超过 120 秒、网站结果超过 150 秒会标为未知。网页每 15 秒更新，可见时本地检查时间，后台暂停轮询。系统仅说明最近一次实际采集的情况，不保证进程存活就代表每项业务功能正常。

状态原子落盘。服务端保存命令已派发后才交给采集器；采集器先持久记录执行中再调用固定的 `systemctl restart <unit>`，不执行任意 shell。通信或执行结果不确定时显示待确认，不自动重复重启。管理员退出会话后，尚在等待读取请求体或队列的操作会再次校验权限。

通知单次尝试，超时/不明确响应显示送达待确认，避免重复刷屏；事件保存在网页，通知链路本身的失败也会显示。维护模式不删除历史事件。采集器读不到的数据不沿用旧健康值。所有历史默认保留最近 24 小时，事件与操作记录有数量上限。

`GET /health` 仅返回服务/网关概况。运营数据必须通过管理员会话读取，采集 token 仅能提交对应主机报告，不能作为网页管理凭据。

## 检查

`npm test` 覆盖状态老化、告警去重、维护模式、命令重复/超时、退出登录竞态、CSRF、采集认证、HTTP/TLS 超时与 KOOK 查询。Python 测试模拟系统命令、网络与持久化，不影响真实服务。GitHub Actions 运行两套检查。
