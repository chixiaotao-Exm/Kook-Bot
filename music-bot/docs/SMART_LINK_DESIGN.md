# 自动识别音乐链接：交互方案

状态：2026-09-17 已接入正式控制台并验证。最初交互原型的示例曲目与队列容量仅用于演示，正式页面通过对应音乐平台读取真实歌曲和歌单信息。

## 统一入口

沿用“正在播放”页面的搜索框，提示改为“搜索歌名，或粘贴歌曲 / 歌单链接”。输入完整链接后识别 QQ 音乐或网易云，并识别歌曲 / 歌单，展示结果卡。粘贴和解析本身不改动播放队列；用户点击“加入队列”或“加入 N 首”后执行。

歌曲显示名称、歌手和平台。歌单显示名称、来源、总歌曲数和少量曲目预览；实际内容由对应音乐平台读取。当前选择的机器人、频道和可用容量始终显示在提交按钮旁。

歌名、关键词与纯数字 ID 仍按用户手动选择的平台处理。识别到链接时平台控件显示链接来源，并标明“链接已自动选择平台”；记住此前的手动选择，继续搜索歌名时恢复使用。

## 提交与边界状态

- 每个操作捕获输入和目标机器人；解析期间切换机器人使旧结果失效，更新新目标和容量后才能提交。已发出的加入操作锁定原目标，结束后解除控件禁用。
- 歌单按实际剩余容量导入，展示“歌单共 200 首，当前可加入 86 首”，按钮为“加入 86 首”。总容量仍为 500 首，包含当前歌曲。已有音乐继续播放；队列为空时沿用现有自动播放行为。
- 导入中禁用重复提交；结果以后台返回的实际 added 数量为准。成功后显示“已为某机器人加入 N 首”，移除当前提交按钮，提供“继续添加”。
- QQ 未登录时提供账号设置入口，保留原链接和目标机器人。登录回来后重新检查权限与容量，继续展示预览，由用户再次点击加入。
- 无法识别时保留输入，提示修改完整链接；网络解析失败提供重试。多条链接不自动合并，提示一次输入一条。
- 首版支持现有两平台可解析的完整歌曲和歌单链接，包括网易云 `#/playlist?id=...`。短链接在预览中明确标注未接入；后续单独实现受限跳转解析，不能把设计演示当作短链接已经可用。

## 视觉与预览

沿用竹青、灰白与现有国漫背景。结果卡内集中显示来源、类型、曲目、容量和目标，避免再弹一次确认框。预览可切换“带曲目预览 / 精简卡片”，并演示 QQ 登录状态和剩余容量。预览交互只改变示例数据，不访问正式服务。

## 后续实现接口

已添加统一输入解析层及只读 `/api/resolve`，返回 `{ source, kind, id, input, isLink }` 和真实预览。实际播放与导入继续调用带明确 `botId` 的现有单曲、歌单接口。歌单写入携带 `maxItems`，服务端按该已审阅数量和实时容量中较小者导入。`expectedVoiceChannelId` 在播放器操作锁内校验，防止解析或登录期间频道发生变化后重新加入旧频道。结果不明的网络错误会要求先检查对应队列再重新预览，不直接重发加入请求。
