# 多人房间使用手册

本文说明专属房间、我的点歌、角色权限和成员动态的使用方式。部署后请在自己的测试频道完成听音验收。

## 进入和分享房间

打开主域名 `/` 或 `/rooms` 查看房间大厅，点击卡片进入 `/room/<机器人ID>`。这里的机器人 ID 是本程序内部编号，默认机器人为 `default`，不是 KOOK 语音频道 ID。管理员已登录时，主域名也仍然显示用户大厅。

房间页显示当前播放、待播队列、我的点歌、网页在线成员、实际 KOOK 语音成员和最近动态。房主可以设置名称、介绍和预设封面主题：竹青 `bamboo`、花影 `blossom`、月夜 `night`，外观编辑可即时预览，保存后生效。封面使用现有去字国漫背景的不同裁切与配色。名称最多 60 字，介绍最多 300 字。

房间的“分享”按钮提供普通链接和二维码。普通分享链接不带管理令牌，可以发给朋友；接收者不会因为打开链接而获得 DJ、房主或站点管理权限。网页本身不播放 KOOK 音频，听歌仍需进入对应 KOOK 语音频道。

网站继续支持 `WEB_REQUIRE_PASSWORD=false` 免密码进入。免密码访问和管理授权是不同设置：陌生访客能够浏览，不会自动取得播放管理、机器人管理或音乐账号管理权限。

## 网页身份

首次打开页面建立一个浏览器身份。填写昵称后成为普通成员，可以在房间点歌。昵称属于网页身份，尚未绑定或验证 KOOK 账号；同名昵称不能证明是同一个人，也不能用来恢复身份或管理权限。

身份保存在 HttpOnly Cookie 中，有效期为 90 天。注销、清除网站 Cookie、身份过期或换用未授权浏览器后，会得到新的身份：

- 旧身份点过的歌仍保留在队列中，但新身份不能在“我的点歌”中认领或撤回它们。
- DJ、房主权限不会通过填写相同昵称自动恢复，需要重新领取相应邀请。
- 站点管理员可打开 `/admin`，使用管理员账号和密码为新的浏览器身份登录授权。不会因此把旧身份的点歌或独立房间角色合并到新身份。
- 修改现有身份的昵称不会改变身份编号或已取得的角色；已保存的点歌记录保留点歌时的显示名。

网页身份与 KOOK 点歌人分别标记。KOOK 点歌显示消息事件中的用户昵称或用户名；网页点歌显示服务器保存的网页昵称，不接受浏览器伪造点歌人编号或他人昵称字段。

D 的角色授权仅属于网页房间。获得网页 DJ 或房主身份，不会自动加入 KOOK 指令管理员名单，也不能替他人投出 KOOK 选票；既有 KOOK 投票和规则仍按真实 KOOK 用户与语音成员查询处理。

## 角色与权限

| 身份 | 可以做什么 |
| --- | --- |
| 访客 `guest` | 浏览大厅、歌曲、队列和成员动态；填写昵称后可点歌和控制播放 |
| 普通成员 `member` | 点歌、导入限额内的歌单、撤回本人待播；在用户房间页共同控制暂停/继续、上下首、音量、进度、循环、随机排序和清空待播 |
| 房间 DJ `dj` | 普通成员功能；管理该房间的播放、切歌、音量及队列；不受普通成员点歌额度限制 |
| 房主 `owner` | DJ 功能；管理本房间资料、频道、常驻、自动电台、定时计划和规则；停止并离开频道；邀请或收回本房间 DJ |
| 站点管理员 `siteAdmin` | 所有房间的房主能力；管理机器人、共用网易云／QQ 登录账号；授予或收回房主权限 |

房主只管理被授权的房间。它不等于站点管理员，不能增删机器人、管理共用音乐账号或为其他房间授权。只有站点管理员能邀请房主或收回房主权限；房主可以邀请、撤销本房间 DJ。

控制台已移至 `/admin/console`，未取得管理角色的访客访问会跳到 `/admin` 登录。管理员登录后默认进入控制台；已获邀请的 DJ、房主也可以从自己的房间进入对应控制页面。播放操作按所选机器人的角色授权，频道与房间设置要求房主，账号和机器人管理要求站点管理员。普通成员、DJ 和房主在房间页点歌；控制台的批量点歌、心动和热歌管理入口仅供站点管理员使用。

普通成员直接在房间页使用共享播放按钮，不需要进入管理控制台或获得DJ授权。操作只作用于当前房间；后台在执行前重新核对身份、机器人实例及频道。同一房间上一项播放操作尚未完成时会提示稍后重试，其他房间独立。

“清空待播”会弹出确认，清除整个房间的待播歌曲，保留当前歌曲、进度和历史。自动电台若已启用，后续可能继续补歌；需要保持暂停可点击暂停，沿用原有电台挂起行为。普通成员不能通过这些按钮让机器人离开频道、修改常驻/电台/定时/角色配置，或操作音乐账号。

权限在服务器校验。点歌、撤回及管理操作在实际修改前再次确认权限和目标频道；等待音乐平台响应期间被撤权、机器人退出或换到其他频道，不会把旧请求写入新的房间。

## 管理员登录与角色邀请

站点管理员使用 `/admin` 登录；普通成员仍可免密码进入公开房间，不需要管理员账号。管理员用户名为 3–40 位英文字母、数字、下划线、点或短横线，并以字母或数字开头；密码为 10–200 个字符，不能包含换行或空字符。

| 入口 | 用途和有效性 |
| --- | --- |
| 普通 `/room/<机器人ID>` 分享链接／二维码 | 邀请朋友浏览和点歌；不包含管理权限 |
| `/admin` 管理员登录页 | 使用账号密码为当前浏览器取得站点管理权限；可以在自己的多个设备登录 |
| 指定房间的角色邀请 | 为一个浏览器身份授予该房间 DJ 或房主；单次使用，创建后 24 小时失效，也可提前撤销 |

账号密码只由站点管理员保管，角色邀请只发给拟授权的人；邀请不能替代普通房间二维码公开发布。接收角色邀请时，在准备长期使用的浏览器中打开并领取。邀请已使用、过期、被撤销或签发者失去相应权限时，不能再次领取。

已登录管理员可以在 `/admin` 修改密码，修改时需要输入旧密码。保存成功后当前浏览器继续保留管理权限，并更换身份凭据；其他浏览器的站点管理授权失效，需要用新密码再次登录。独立授予的房间 DJ、房主角色不受影响；由旧站点管理授权签发但尚未领取的邀请会失效，需要重新生成。

“退出管理”只撤销当前浏览器的站点管理授权，保留昵称、独立房间角色和“我的点歌”；之后仍可以作为普通成员或已有房间角色继续使用。它不同于注销整个网页身份，注销身份或清除 Cookie 后不能凭原昵称找回旧点歌。

管理员密码只保存 scrypt 加盐哈希。登录有尝试频率限制；用户名或密码错误统一提示，连续失败时需按页面提示稍后重试。继续使用 `WEB_REQUIRE_PASSWORD=false`，不要为了管理员登录开启整站入口锁；旧的 `npm run admin`、`data/web-admin.json` 不是这里的管理员账号配置。

从旧版迁移时，首次配置账号会停用 `/rooms#admin=…` 站点管理长链接，同时保留现有浏览器的站点授权、独立房间角色及尚未领取的有效房间邀请。以后使用 `/admin` 登录即可。旧的 `scripts/room-admin.js` 仅为历史兼容保留，启用账号后会拒绝重新生成长链接。

收回 DJ 或房主授权后，该网页身份通常仍是已填写昵称的普通成员；收回管理角色不是禁止其浏览或普通点歌。房主和 DJ 不能通过自己发出的旧邀请重新获得已经被收回的管理权。

### 初始化或重置管理员账号

首次部署、从长链接迁移或忘记密码时，使用 `scripts/admin-login.js`。必须先停止服务，避免运行进程用旧内存状态覆盖权限文件。配置成功后再启动；首次迁移保留现有授权，已有账号再次重置会撤销全部旧站点管理授权和其未领取邀请，独立房间角色、昵称及点歌记录继续保留。

在服务器私有目录准备一个只有服务用户可读的密码文件，例如 `/opt/kook-music-bot/data/admin-password.txt`，权限设为 `600`，内容只放新密码，可带一个结尾换行。使用私密编辑器填写，不要把密码写进命令行参数或 shell 历史。下面的 `YOUR_ADMIN_NAME` 应替换为准备使用的管理员用户名，Node 路径应与实际服务配置一致。

```bash
sudo systemctl stop kook-music-bot
cd /opt/kook-music-bot
sudo -u kookbot /opt/kook-node/bin/node scripts/admin-login.js --username YOUR_ADMIN_NAME --password-file /opt/kook-music-bot/data/admin-password.txt --data-dir /opt/kook-music-bot/data
sudo systemctl start kook-music-bot
```

命令只输出成功提示和用户名，不打印密码或哈希。命令成功后及时删除临时密码文件，打开 `/admin` 登录。不能把密码文件放进 `web/`、发布包或共享截图。若命令报告原权限文件损坏，检查并恢复原文件，不能用空权限文件直接覆盖现有身份。

Docker Compose 使用相同数据卷执行 CLI，不能另建临时空目录。以下将准备好的主机私密密码文件只读挂载到临时容器；需替换实际文件路径和用户名：

```bash
docker compose stop bot
docker compose run --rm --no-deps -v /PRIVATE_DIRECTORY/admin-password.txt:/run/admin-password.txt:ro bot node scripts/admin-login.js --username YOUR_ADMIN_NAME --password-file /run/admin-password.txt --data-dir /app/data
docker compose up -d bot
```

忘记密码无需更改 `WEB_REQUIRE_PASSWORD`，也无需退出网易云或 QQ 音乐账号。若只想收回某个 DJ／房主，使用对应房间的角色管理即可，不必重置站点密码。

## 点歌与我的点歌

在专属房间输入歌名、ID 或支持的网易云／QQ 歌曲和歌单链接。链接自动识别平台；普通歌名和数字 ID 使用选中的平台。官方短链接的支持范围沿用 [ROOM-FEATURES.md](ROOM-FEATURES.md#手机分享短链接)。

普通成员在每个房间默认最多点 5 首，包含本人当前播放和待播歌曲。房间启用点歌规则时，沿用配置的每人上限和同源同曲去重设置；DJ、房主与站点管理员不受普通成员额度限制。全部来源共用该机器人的总队列容量，默认正式配置最多 500 首，包含当前歌曲。

歌单只加入实际可容纳的数量，并返回加入结果。一个成员在同一房间已有点歌请求处理中时，需要等待该请求结束；连续点歌还受短暂冷却限制。音乐会员、版权、地区和登录状态仍决定能否取得完整可播放音源。

“我的点歌”只列出当前身份的待播项。撤回依据稳定的队列条目标识，洗牌或他人移除前面的歌曲不会误删别人的歌。当前歌曲已开始播放、条目已不存在或属于他人时不能撤回；切歌和全队列管理需要 DJ 等相应权限。

网页和 KOOK 身份尚未合并。同一人用 KOOK 指令点的歌曲不会凭网页同名昵称成为“我的点歌”。已有 KOOK 管理员白名单和同语音频道要求仍独立生效。

## 排队位置与等待估算

队列显示前方歌曲数量和按当前顺序估算的等待时间。它不是承诺的开始时间：切歌、插播、队列排序、播放异常和音源跳过都会改变结果。

暂停、单曲循环、当前歌曲正在恢复／等待，或相关歌曲时长缺失时，等待时间显示“暂无法估算”。队列循环下显示的是沿当前队列下一次轮到该条目的估算，不预测后续多轮播放。

## 成员在线与活动记录

网页与语音成员分别统计：

- 网页房间页在可见时发送心跳，记录有效期 60 秒。同一身份开多个标签页只计一人；普通读取接口或大厅浏览不会自动把人登记进每个房间。
- 关闭或离开页面后，网页记录可能保留至心跳过期；这段时间不能视作持续在线证明。
- 语音名单来自机器人实际查询的 KOOK `channel/user-list`，每个机器人缓存 30 秒，并合并并发读取。首次查询显示“正在读取”，不会假装为零；缓存过期时在后台刷新，不阻塞当前歌曲、队列、身份和权限的更新。语音人数只统计真人，机器人成员可以在名单中独立显示。
- 查询失败时人数为“未知”；上次成功名单仍可展示，但明确标记为旧数据。网页心跳不会补成语音人数。

房间动态保留最近 100 条，涵盖点歌、撤回、开始播放、播放控制、网页进入／离开、检测到的 KOOK 语音成员变化和角色／资料操作。语音变化按轮询发现时间记录，不保证等于客户端真正进入或离开的秒数。没有在 KOOK 频道额外广播这些网页动态。

## 持久化与备份

升级和备份应保留整个私有数据目录。不能用预览身份、队列或角色文件覆盖生产数据。

| 文件 | 内容 |
| --- | --- |
| `.env` | 默认机器人 Token、运行配置与可能配置的音乐凭据 |
| `data/room-access.json` | 网页身份哈希、有效期、房间角色、邀请哈希、站点授权版本及管理员用户名和 scrypt 密码哈希 |
| `data/social-rooms.json` | 房间名称／介绍／主题、各房间最近 100 条活动 |
| 旧 `data/admin-entry.txt` 或旧 CLI 指定的私有输出文件 | 历史管理长链接；迁移到账号登录后失效，不再作为当前入口 |
| `data/queue.json` | 默认机器人的当前歌曲、队列、稳定条目标识、点歌人、进度、历史与设置 |
| `data/bots.json` | 新增机器人的私有 Token 与配置 |
| `data/bots/<机器人ID>/queue.json` | 对应机器人的独立播放状态和条目标识 |
| `data/room-features.json`、`data/bots/<机器人ID>/room-features.json` | 自动电台、计划、规则和执行账本 |
| `data/netease-cookie.json`、`data/qq-credential.json`、`data/qq-device.json` | 音乐账号登录与 QQ 设备信息 |
| `data/health-events.json`、可选的 `data/web-admin.json` | 故障历史与可选入口密码哈希 |

网页在线心跳和语音名单缓存不持久化，服务重启后重新建立。播放器读取旧版本队列时会为缺少标识的条目生成并保存稳定 ID，保留歌曲、进度和点歌来源；旧记录缺少昵称时显示相应来源的通用名称。

这些文件和备份包含账号、身份或管理能力，应与服务器凭据同等保管。通过 CLI 重置管理员账号、手工恢复身份权限文件和替换完整数据备份都应先停服，再使用与服务相同的用户、数据目录和 Node 运行环境处理。临时明文密码文件配置成功后即删除，不作为日常备份内容；旧版权限备份仍可能带有曾经有效的长链接授权，不能直接覆盖升级后的权限文件。

## 本轮未新增的能力

本轮不增加响度归一化／均衡处理，不修改现有音频发送链路；不增加网页与 KOOK 共用投票、不增加按点歌人轮流插队的公平排序，也不增加网页昵称与 KOOK 账号绑定。已有 KOOK 指令投票、自动电台、定时计划、联合搜索、歌词和故障中心继续按原功能运行。
