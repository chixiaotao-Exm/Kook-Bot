# 房间功能手册

本文说明本版本的功能和操作方式。部署后请在自己的测试频道验证播放与权限。

## 入口和作用范围

| 功能 | 页面入口 | 作用范围 |
| --- | --- | --- |
| 自动电台 | 左侧“房间设置”→“自动电台” | 顶部选中的机器人 |
| 定时播放与音量 | 左侧“房间设置”→“定时计划” | 顶部选中的机器人及其当前已选频道 |
| 多人点歌规则 | 左侧“房间设置”→“点歌规则” | 该机器人处理的 KOOK 文字操作 |
| 手机分享链接 | 原搜索框或“导入歌单” | 预览显示的目标机器人 |
| 双平台搜索 | 搜索区域的平台按钮→“联合搜索” | 浏览结果，点击歌曲后加入所选机器人 |
| 同步歌词 | 左侧“歌词” | 顶部选中的机器人正在播放或暂停的歌曲 |
| 故障与账号提示 | 左侧“故障中心” | 所有机器人和共用的音乐账号 |

自动电台和 KOOK 点歌规则初始关闭，初始没有定时计划。设置按机器人独立保存；切换页面所选机器人不会替其他机器人启用功能。网易云、QQ 音乐账号仍由全部机器人共用。使用自动播放前，先为对应机器人选择并连接语音频道。

## 自动电台

打开“房间设置”→“自动电台”，选择音乐来源与选曲方式，开启“自动续播”，点击“保存自动电台”。支持网易云、QQ 音乐，以及双平台交替加入候选歌曲；选曲方式为热歌榜、ACG 歌单或指定歌单。指定歌单需要选择单个平台，可填写歌单 ID、官方完整链接或支持的分享短链接。

默认在待播歌曲不超过 2 首时，尝试补充 10 首，并避开最近 50 首记录。可以调整为：

| 设置 | 可选范围 | 含义 |
| --- | --- | --- |
| 补歌水位 | 0–20 首 | 待播数量不超过该值时尝试补歌；不计正在播放的歌曲 |
| 每次补充数量 | 1–50 首 | 实际数量还受可用候选歌曲及队列剩余容量限制 |
| 近期歌曲去重范围 | 0–200 首 | 参考近期自动补入记录及可用播放历史；0 表示不额外排除历史歌曲 |

当前歌曲和待播队列始终参与自动补歌去重。去重按“平台＋歌曲 ID”判断，不把不同平台或不同版本强行认作同一首。双平台模式中，一个平台失败时可以使用另一个平台成功返回的候选结果；不会替换已经选择的歌曲版本。

自动任务通常每 10 秒检查一次，补歌尝试至少间隔一分钟。没有未重复歌曲、账号不可用或平台暂时失败时，保留现有队列并显示错误，稍后再尝试。它是基于榜单／歌单的自动补歌，不是个性化推荐模型。

手动暂停会挂起自动电台，关闭页面不会恢复播放。可手动恢复播放，或在启用自动电台的状态下重新保存设置以解除挂起；已有暂停曲目仍需恢复播放。停止并离开后不会由电台自行把机器人拉回频道。每个机器人的队列总容量仍由 `MAX_QUEUE_SIZE` 决定，当前正式配置为 500 首，包含当前歌曲。

## 定时计划

打开“房间设置”→“定时计划”→“添加计划”，填写名称、星期、时间、时区和操作后保存。每个机器人最多 20 条计划，可分别编辑、停用和删除。新建编辑器默认北京时间 `Asia/Shanghai`、每天 20:00；保存时的“保存后启用”决定是否启用该计划。也可以使用 `America/Caracas`、`UTC` 等有效 IANA 时区，执行时间按计划所填时区计算，不跟随浏览器所在地自动变化。

| 操作 | 到时执行的行为 |
| --- | --- |
| 追加热歌并播放 | 按剩余容量把所选平台热歌追加到队尾，并开始或恢复播放 |
| 追加歌单并播放 | 读取指定歌单，按剩余容量追加到队尾，并开始或恢复播放 |
| 暂停播放 | 保存当前进度并暂停，同时挂起自动电台 |
| 恢复播放 | 按现有队列和保存进度恢复；空队列不会因此生成歌曲 |
| 调整音量 | 修改该机器人的音量为 0–100%，不切换歌曲 |

歌单／热歌计划保留原队列顺序和当前歌曲，不清空队列、不强制插播；如果当前暂停，会从保存位置恢复，再依次播放追加内容。添加时排除已经在当前／待播队列中的歌曲。队列已满、所有候选均重复或账号不可用时，查看计划的最近执行信息及“故障中心”；未选择频道时跳过检查。

计划按指定星期的对应分钟检查，不保证精确到某一秒。服务停止、阻塞或未选频道期间错过的计划不会补跑；服务启动、新建或修改计划所在的当前分钟也不会立即补执行。已登记执行的计划不会因服务重启在同一当地日期重复追加，失败后同日不自动重试该条计划。若需要立即执行，请手动加入歌单或操作播放器。

计划绑定机器人，不单独绑定一个永久频道；执行时使用该机器人的当前已选频道。更换机器人所处频道后，应一并检查其现有计划是否仍合适。

## 手机分享短链接

把手机 App 的分享内容直接粘贴到原搜索框，或使用“导入歌单”。一次只处理一条链接，分享文本最多 2000 字。识别后仍显示平台、歌曲／歌单、目标机器人和可加入数量，确认后才加入队列；不要求先手动切换平台。普通歌名和纯数字 ID 保持原先的手动平台选择规则。

目前可尝试展开的短链域名：

- 网易云：`163cn.tv`、`163cn.com`。
- QQ 音乐：`c.y.qq.com`、`c3.y.qq.com`、`c5.y.qq.com`、`c6.y.qq.com`，以及官方 `y.qq.com`／`i.y.qq.com` 的部分分享跳转路径。

最终地址必须是已支持的官方歌曲、歌单或榜单链接。完整链接的官方域名为网易云 `music.163.com`／`y.music.163.com`，QQ 音乐 `y.qq.com`／`i.y.qq.com`。暂不支持通用 `url.cn` 短链、其它平台、需要执行网页脚本／验证码才能展开的页面，或存在多个不明确目标的分享页。平台修改分享格式时，可能仍需回到官方页面复制完整链接。

解析只读取官方分享地址，不向分享服务器发送网易云／QQ 账号凭据。每次最多跟随 5 次跳转、总计 8 秒、读取 256 KB；每一步校验官方域名并固定公开 IP，拒绝内网地址及非标准端口。

短链跳转、文本提取、安全限制已通过模拟网络响应验证；这不表示所有手机型号、所有 App 版本生成的真实分享短链均已实测。官方短链不可用时，完整链接和纯 ID 入口仍可使用。

## 联合搜索

在搜索区域选择“联合搜索”，输入歌名或歌手。页面分别展示网易云和 QQ 音乐结果，每首保留来源、歌手及版本信息。点击你需要的版本加入当前机器人，混合队列按原顺序播放。

单个平台超时、限流或失败时，仍显示另一平台的成功结果，并标明失败的平台。两边的同名歌曲不会被自动合并，也不会在播放失败时偷偷替换成另一平台版本。粘贴歌曲／歌单链接时，仍按链接实际来源进入预览。

联合搜索只扩大查找范围，不改变播放权限。QQ 完整播放需要有效登录，会员、地区或购买限制仍由各平台与当前账号决定。

## 故障中心

左侧“故障中心”集中显示全部机器人的消息网关、语音连接、当前曲目及需要关注的状态，同时显示网易云与 QQ 账号的检查时间和状态。“最近事件”展示连接恢复、音源问题、自动任务、设置与账号等记录；“重新检查账号”请求重新核查账号，平台请求频率受后台限制。

页面每 15 秒刷新显示；后台约每 10 秒采样机器人状态，通常每 5 分钟核查账号。最多保留 300 条事件，重启后可以读取已保存的记录。帐号或平台检查失败不等于账号一定失效，应结合页面中的错误与检查时间判断。

此页不会因一条诊断记录主动重启服务、换曲或更换音乐平台。网关在线、RTP 连接、歌曲进度和歌词高亮只能说明服务器侧状态；“频道里是否真正听到声音”仍需 KOOK 客户端听音确认。原有播放器的断线重连和有限播放恢复继续独立运行。

## 同步歌词

选择机器人后打开左侧“歌词”，查看其当前歌曲的歌词。时间高亮跟随该机器人的播放进度；暂停时停止推进，切歌或切换机器人后读取对应歌曲。支持平台返回的翻译，可用“显示译文”开关控制；“沉浸歌词”放大显示，按 Esc 或点击退出按钮返回。

网易云和 QQ 均通过各自接口读取歌词。带时间戳的 LRC 显示同步行，无时间戳时显示纯文本；纯音乐、无歌词或请求失败会给出提示，不影响音频播放。翻译只在平台实际返回且时间能对应时显示。暂不提供逐字卡拉 OK、歌词编辑、下载或自动翻译；歌词时间准确度受上游内容影响。

## 多人点歌规则

选择机器人，打开“房间设置”→“点歌规则”，开启“启用 KOOK 点歌规则”后保存。默认参数为每人 5 首、阻止重复歌曲、投票切歌需要 2 票，但初始总开关关闭。

- 每人额度包含该成员点的当前歌曲与待播歌曲；批量加入也受额度和队列容量限制。
- 去重按平台与歌曲 ID 判断，检查当前歌曲和待播队列。
- 开启投票后，普通成员的 `/切歌`、`/下一首` 或 `/投票切歌` 会投出一票；相同成员对同一首只计一次。
- 只有当前语音频道中的真人成员可以投票。实际门槛取配置票数与频道真人数量的较小值；已离开的成员在下一次投票核实时不再计数，新曲目清零票数。
- 房间管理员可以直接切歌，并使用暂停、恢复、上一首、音量、循环、常驻和队列管理指令。管理员可在房间设置填写 KOOK 用户数字 ID，原 `.env` 中的 `ADMIN_USER_IDS` 继续有效。
- 普通成员可用 `/规则` 查看当前规则；关闭投票开关后，切歌由管理员执行。

KOOK 文字指令继续按真实 KOOK 用户、同语音频道检查及这里的管理员设置处理。新增网页房间采用独立的浏览器身份和成员／DJ／房主权限；网页普通成员默认限额为 5 首，开启本房间规则后沿用配置的额度与去重。网页 DJ 身份不会自动成为 KOOK 指令管理员，也尚未接入网页投票。旧控制台对未授权访客只读，管理操作需要对应网页角色，详情见[多人房间手册](SOCIAL-ROOMS.md)。自动电台和定时计划不占用某位成员的点歌额度，继续独立遵守容量、去重和频道变更检查。

## 升级与数据保存

新功能沿用现有 Node、Python QQ 接口和 FFmpeg，不新增公网端口。更新前端后运行 `npm run build:web`；后端及 QQ 进程协议也有变化，正式更新需要按既有部署流程重启服务，不能只替换前端静态文件。生产账号与数据不能用预览文件覆盖。

除了已有 `.env`、账号凭据、多机器人定义和队列，请在私有备份中保留：

| 文件 | 内容 |
| --- | --- |
| `data/room-features.json` | 默认机器人的电台、计划、规则、自动任务执行记录 |
| `data/bots/<机器人ID>/room-features.json` | 对应额外机器人的独立房间配置与执行记录 |
| `data/health-events.json` | 全局故障与恢复事件 |

首次没有房间配置文件时使用关闭自动电台、关闭点歌规则、无定时计划的默认值，不自动启用这些功能。损坏的房间配置不会被静默覆盖；应保留原文件和备份后排查。故障历史读取失败时保留原文件，页面显示保存／读取提示。

QQ 接口执行并发上限为 4，单个执行请求与排队请求使用独立超时；一个请求超时只取消它自己的任务。QQ 限流仍按对应方法冷却，不绕过上游限制。升级验收建议先在本地预览或隔离数据目录验证，再检查正式实例的原频道、队列、进度和账号，实际听音另行确认。
